## Summary

The browser extension content script (`content.js`) renders widget content into iframes via `createIframeMount()` when the WASM module indicates the content needs script execution (`parts.needs_iframe` or `parts.js` non-empty). The iframe content (generated by the WASM module) is NOT independently sanitized by the content script before insertion. The iframe has `sandbox="allow-scripts"` (no `allow-same-origin`), so scripts can execute but cannot access the parent page. This is by design but presents a risk surface.

## Vulnerable Code


**`createIframeMount` at lines 259-283:**
```javascript
function createIframeMount(renderFrameDoc) {
    let frameDoc;
    try { frameDoc = renderFrameDoc(); } catch (error) { return null; }
    const srcdoc = frameSrcdoc(frameDoc);
    if (!srcdoc) { return null; }
    const mount = document.createElement("div");
    const frame = document.createElement("iframe");
    frame.sandbox = "allow-scripts";
    setIframeDocument(frame, srcdoc);
    attachFrameResize(frame);
    mount.append(frame);
    return mount;
}
```

**`setIframeDocument` at lines 164-175:**
```javascript
function setIframeDocument(frame, srcdoc) {
    frame.removeAttribute("src");
    try {
        const blob = new Blob([srcdoc], { type: "text/html;charset=utf-8" });
        const url = URL.createObjectURL(blob);
        frame.src = url;
    } catch (_) {
        frame.srcdoc = srcdoc;
    }
}
```

## Attack Scenario

1. Third-party page contains a `<pre>` element with crafted content
2. WASM module's `extract_specs` / `extract_widgets` parses the content and returns a spec
3. WASM module's `render_frame_doc` generates an HTML document with the spec
4. If `parts.needs_iframe` is set (which depends on WASM logic), the content is rendered into an iframe WITHOUT going through `sanitizeHTML`
5. The iframe has `sandbox="allow-scripts"` but the content is not sanitized by the content script

## Root Cause

When the iframe path is taken (rather than the `createInlineAnywhereMount` path), the WASM module's HTML output bypasses `sanitizeHTML()`. The iframe sandbox provides partial protection, but:
- The iframe can execute arbitrary JavaScript
- The content script's `attachFrameResize` listens for `message` events from iframes — the iframe can send spoofed resize messages
- Blob URL origin behavior varies by browser — some browsers may grant unexpected capabilities to blob-originated scripts

## Evidence

- `content.js:342-345` — `createIframeMount` called when `needs_iframe` or `parts.js` is non-empty
- `content.js:269-270` — iframe has `sandbox = "allow-scripts"` only
- No call to `sanitizeHTML()` on the iframe content path

## Existing Mitigations

- `sandbox="allow-scripts"` without `allow-same-origin` prevents parent DOM access
- Iframe content is isolated from the parent page's origin
