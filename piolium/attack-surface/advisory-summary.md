### Highest-Risk Flows

1. **RawHtml SSR XSS** (patched): `crepuscularity-web` `render_ssr_node` used unsanitized HTML — now mitigated via `ammonia::clean`
2. **Dev server path traversal** (patched): `/islands/` handler served arbitrary files — now mitigated via canonicalized path checks
3. **Config path traversal** (patched): Guest paths and prelude scripts had insufficient path validation
4. **Extension content script XSS** (patched): Content script injected unsanitized HTML into pages — now mitigated via `sanitizeHTML()` DOMParser-based allowlist
5. **Plugin subprocess injection**: All plugin bindings (Python, PHP, Go, TS/Bun, Ruby) call `crepus native ir` with caller-controlled template paths; no validation of the path argument before subprocess invocation

### Patch Quality Signals

- **`crepuscularity-web`** had a RawHtml XSS fix using `ammonia::clean` — this is a standard sanitization approach, but the need for it suggests design-level exposure (raw HTML rendering with user-controlled content is inherently risky)
- **`crepuscularity-cli`** had TWO separate path traversal fixes within 7 days (dev server + config loader) — this signals a **structural-recurrence** pattern in path handling that should be audited comprehensively
- **`crepuscularity-webext`** had an XSS fix in the content script — the `sanitizeHTML()` DOMParser approach is reasonable, but should be verified against edge cases (nested SVG/MathML, mutation XSS)

### Audit Targeting Recommendations

> Based on pattern analysis:
> - **Phase 3** should prioritize `crepuscularity-web` (SSR rendering), `crepuscularity-cli` (config + dev server), and `crepuscularity-webext` (content script) for DFD slices
> - **Phase 5** deep probe should target (1) HTML/template rendering entry points with XSS focus, (2) file path resolution logic for traversal, (3) plugin subprocess invocation for command injection
> - **Phase 10** chambers should include XSS (CWE-79) and Path Traversal (CWE-22) as mandatory attack modes
> - **Patch-bypass-checker** should flag `crepuscularity-cli` path handling and `crepuscularity-web` HTML sanitization as structural-recurrence candidates
