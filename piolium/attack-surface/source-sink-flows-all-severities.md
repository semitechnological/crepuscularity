## Flow Paths

### Plugin Path Injection Flow
```
User input → plugin bindings → path argument (unvalidated)
  → [crepus native ir path] subprocess (all languages)
  → File.read(path) / os.ReadFile(path) / Bun.file(path).text()
  → template content sent to subprocess via stdin JSON
  → NO canonicalization, NO prefix check, NO symlink rejection
  → Attacker reads arbitrary files
```

### Hydration Payload Flow
```
SSR server → render_ssr_document → append_hydration_payload
  → serialize_ctx_for_ssr() → base64 encode → <script id="__crepus_hydration__">
  → Client WASM runtime parses and uses as reactive state
  → NO HMAC, NO signature, NO integrity check
  → Stored XSS/MITM can tamper with hydration state
```

### Content Script Sanitization Flow
```
Third-party page → <pre><code> markdown → content.js extracts text
  → WASM render_anywhere_parts() → sanitizeHTML()
  → innerHTML = sanitizeHTML(html) + shadow DOM attachment
  → URL validation: startsWith("/") allows protocol-relative URLs
  → Attacker can inject //evil.com/phish links
```

### V8 Bridge Invoke Flow
```
JavaScript (V8 guest) → Crepus.invoke(plugin, method, payload)
  → Bridge::invoke_inner → capability check → plugin::invoke
  → FsPlugin: resolve_under_sandbox() → std::fs operations
  → No rate limiting, no payload size limit, no depth limit
  → Attacker exhausts resources or calls invoke in tight loop
```
